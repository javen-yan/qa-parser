# 客户最少操作约定

当前实现已包含 Mac 核心、CLI 和最小本地界面，启动方式见 `docs/local-ui.md`。

客户只需选择输入文件、必要题型和输出位置，启动转换。程序自动选择已配置的组件、执行文本公式转换、可靠原图兜底、校验及导出，不要求客户选择引擎、安装组件、修正公式或逐题确认。组件配置、安装和随包分发属于开发与交付责任。

结果状态严格区分：

- 成功：全部题目完成文件转换。
- 部分失败：明确显示已导出/总数、未导出题号与简洁原因，突出“结果不完整”；已通过结果可直接取用。
- 失败：无可用结果或无法完成处理，给出易懂原因与诊断位置，不将空Excel作为成功结果。

核心的 `summary.json.user_result` 是后续界面的展示接口；`result.txt` 为可定位的客户报告。原始异常、字体/编码/转换引擎和对象位置保留在诊断JSON或错误日志，不直接作为客户错误提示。

本地界面提供输入区、启动按钮、处理进度与上述三态结果区；结果区提供打开成功文件和查看报告入口。转换细节放在可选诊断信息中，不插入确认对话框或逐题操作流程。当前界面不等于已经完成客户运行时打包或真实系统导入验收。

## 本次验证

104 项自动测试通过。九份样本各识别 100 道题，共 900 道；831 道导出，69 道隔离。三份文档全部成功，六份部分失败。重复转换的语义一致，独立读取导出 Excel 核对通过。证据位于 `outputs/customer-flow-validation/summary.json`，各文档目录中的 `result.txt` 保存客户提示。这里的通过仅指程序检查，不替代全部公式的人工语义核验及真实系统导入验收。
