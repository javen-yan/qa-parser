# 第一阶段技术决定

后续自动处理已实现，当前行为见 `automatic-processing.md`。原来的“先做人工复核”优先级已替换为可靠LaTeX、原始预览PNG、自动隔离三条路径；本文件保留内核选型依据。

## Python 内核加 CLI

本轮选择 Python 编排，不将 Rust 作为前提。已选公式组件主要提供 Python 接口；直接复用能避免移植成熟解析逻辑。项目自己的代码集中在题目归属、字段映射、组件状态、资源管理和导出门禁。

接口不绑定 UI：读取器返回有位置的 token；公式适配器统一返回 LaTeX/status/reason；核心组织题目；导出器接受已校验任务。后续 UI 可调用库或使用 CLI/JSON 边界。暂不决定最终桌面壳和私有运行时打包方案。

## 依赖包级复用

| 能力 | 采用组件 | 使用范围与依赖 |
|---|---|---|
| DOCX ZIP/XML/资源 | Python zipfile + lxml 6.1.3 | ZIP和XML能力直接复用；业务层遍历OOXML以保留OLE和源位置。lxml包含原生扩展，本机通过wheel安装；其他平台需对应构建，尚未运行验证。 |
| OMML | omml2latex 0.1.1 | 小型Alpha包，增加保守检查，未知结构复核；不是仅因有开源就全量放行。 |
| MathType/OLE | olefile 0.47 + 固定版本MIT单文件MTEF模块 | 不引入整个上游项目；删除其CLI和自研OLE回退，仅复用公式节点解析/转换。 |
| 图片 | zipfile资源读取、标准库复制及SHA-256 | 保留原始图像编码，不引入重型转换程序。样本插图为PNG/JPEG；特殊格式及变换未支持时复核。后续有转换需求再验证Pillow/对应格式小工具，不假定其能处理所有WMF/EMF。 |
| XLSX | XlsxWriter 3.3.1 | 纯Python写出，文本单元格，不依赖Excel；测试独立读取ZIP/XML验证。 |
| 渲染预览 | 本阶段不集成 | 当前没有UI；KaTeX/MathJax等在后续预览阶段用真实公式验证，不能把源码转换通过当作渲染通过。 |

精确开发依赖见 `requirements-dev.lock`，运行依赖见 `requirements.lock`。公式候选、固定来源、维护情况和许可详见 `formula-components.md`。

## 自研范围

新增的是DOCX节点到统一token的适配、题号/选项/答案业务规则、模板配置、任务与资源指纹、CLI和问题报告。没有自研ZIP、XML解析器、OLE容器、MTEF完整格式或XLSX文件编码器。

使用手写可见题号的现有样本作为首版格式范围。自动编号、特殊嵌套内容和不确定布局明确复核。以后扩展须提供失败样本、预期语义和回归测试，优先检查现成包能力，再考虑有限补丁。

## 平台与发布边界

当前代码不调用Office、MathType、shell转换命令或系统安装位置；使用pathlib处理本地路径，图像原始格式不改名伪装。实际测试平台仅macOS ARM64/Python3.13.3。

尚未制作客户应用。未来Windows便携包需要随包提供运行时及原生扩展，测量总体积、检查DLL/字体/许可，并进行实际运行验收。Python开发环境依赖不能转嫁为客户安装前提；本轮不开展Windows环境寻找、CI或打包。
