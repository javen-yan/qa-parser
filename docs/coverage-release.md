## 第 1 题的实际输出

`MathType公式化学2.docx` 第 1 题现已导出，Excel 第 2 行，原答案 B 未改：

```text
A．铁+氧气$$\xrightarrow{\text{点燃}}$$四氧化三铁
B．氧化钙+水→氢氧化钙
C．磷+氧气$$\xrightarrow{\text{点燃}}$$五氧化二磷
D．氯酸钾$$\xrightarrow{\Delta}$$氯化钾+氧气
```

箭头来自 selector 14 的方向位、上下 LINE 和显式 U+2192；条件文字来自 Unicode MTCode。三个对象均不再依赖 WMF。真实样本是右箭头与非空上条件；左箭头、非空下条件和上下同时有文字的支持由规范及合成结构测试验证，未声称有对应真实文档视觉验收。

开发对照为 `output/coverage/comparison.html`；实际 WKWebView 截图为 `output/coverage/q1-native.png`、`representatives-native.png`、`prescript-native.png`。第1题做了截图对照；其他代表式做了原始结构/字符测试及原生显示核对，不等于 Word 逐像素比对。

## 唯一仍未导出的题

`MathType公式化学填空2.docx` 第 62 题，答案三个对象原始 `oleObject166–168.bin`，Word 段落 p528–530。当前任务编号 F000318–F000320；旧基线编号 F000319–F000321 因前面 Word run 合并发生移动，源对象 SHA/XPath 不变。

三个矩阵均为两行一列、无分隔线，但对齐字节是 `(1,129,129)`。当前确认的格式枚举不解释 129 的高位，不能直接清除 0x80 或默认为居中。UI 展开诊断能看到精确 alignment/rows/cols/partitions。行列内容仍存在，不是文档无法读取。

实际尝试过候选 mathtype2omml 的 MTEF→MathML：三个对象均有输出，但源码将未知 -127 映射为默认 center，不能作为对齐正确的证明。libwmf 与本机 LibreOffice 的离线 WMF 探测仍出现空白、字母替代符号或中文方框，没有将这些图放入客户包。详情见 [结构适配与候选实测](mtef-coverage-extension.md)、[字体绑定与渲染探测](mtef-font-bindings.md)。

下一步需要更新格式规范/可交叉验证的高位语义，或可再分发字体与矢量渲染器的保真验证。这一缺口保留证据，不以猜测位置换取 900/900。

- 最终完整测试：284 项通过。涉及上下条件方向、缺槽位/冲突标志、分式/上下标、矩阵/空行、字体定义、私有码类型、记录边界、资源绑定、任务恢复和导出。

- 本轮新变为 LaTeX 的182条源对象映射全部通过固定 KaTeX 的严格离线渲染。
- 全量4709个已转换公式中，严格 KaTeX 预览4459个可渲染，250个触发明确源码回退（OMML79、Word run116、MathType55）。主要涉及既有裸中文、全角符号、圈号和零宽字符等表示兼容性；此数字不是源公式语义丢失率，也不是目标APP实测结果。已记录所有表达式和具体渲染异常，不能把它们计成预览全部成功。

- 同版本、同输入/config 的稳定难度算法未改；本轮公式规范化文本改变可能改变对应题目的散列难度。冻结与开发版的输出难度已一致。

## 后续兼容方式

按文档格式/版本与能力族选择解析适配器，统一输出带源位置的结构树，再做规则校验与 LaTeX/可靠原图表示选择。未知记录显式失败；已知元数据只按完整标识识别，不能一律跳过。新增规则必须有规范/成熟实现依据、正反例、组合与递归测试；九份文档只承担端到端回归。

本次保留少量互补组件。更广的 MTEF→MathML 候选先作开发端独立对照，验证未知值行为、语义保留与许可后再决定替换主组件。不能把“另一个库输出成功”当成自动兜底，也不将完整办公套件、多个语言运行时全部塞入客户包。候选支持、许可、维护证据及实际验证边界见 [开源方案与规范能力矩阵](formula-ecosystem.md)。
